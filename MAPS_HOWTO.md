# Building a map

Every map owns its own files. A builder edits only the files listed for its map and never touches another map's files or the shared engine files. All 16 Polyfork maps are already registered, so no shared list needs editing.

## Files a map owns

| File | What it holds |
|---|---|
| `src/shared/maps/<map>.zig` | `pub const def: api.Def`: name, note, tint, size, palette, terrain height and colour, layout (`build`), spawns and loot (`spots`) |
| `src/shared/maps/<map>_kit.zig` | Generated by the Blender script: prop kinds `K`, the prop table, building footprints. Do not hand-edit |
| `tools/blender/maps/<map>.py` | Lists the Polyfork models to export and their scales |
| `src/client/assets/props/<map>/` | Exported `.glb` models, written by the Blender script |
| `src/client/assets/ui/maps/<map>.png` | 480x240 map select preview |

The engine side lives in `src/shared/maps/api.zig` (the `Def` struct and helpers) and `src/shared/maps/registry.zig`. Do not edit them, `world.zig`, `terrain.zig`, `props.zig` or any client file. If you need an engine hook that does not exist, say so in your report instead.

## Steps

1. **Download the kit.** `tools/polyfork_fetch.sh <kit-slug> ~/.cache/polyfork/<map>` downloads every GLB, its hero render (`<id>.png`), the kit cover (`cover.jpg`) and `index.tsv` (id and name). Look at the renders and pick what you need. One kit is often not enough for a 300 to 500 m map: you may also pull single models from other kits in the same style (`https://polyfork.dev/cdn/<id>.glb`, ids in the catalog's `catalog.json`).
2. **Write `tools/blender/maps/<map>.py`.** Copy `tools/blender/maps/racing.py`. Each building entry is `(name, polyfork_id_or_parts, {opts})`, where a part list is `[(id, (x, y, z), yaw), ...]` to glue modules into one building. Each prop entry is `(name, id, {opts})` with `scale`, `k` (rgb tint multiplier), `group` (`tree`, `rock`, `bush`, `ground`, `building`, `road`, `street`, `car`) and `collide` (`none`, `box`, `cylinder`, `trunk`).
3. **Export.** `tools/mapkit.sh <map>` runs Blender headless. It writes the GLBs to `src/client/assets/props/<map>/` and generates `src/shared/maps/<map>_kit.zig`, then prints triangle counts. Polyfork vertex colours are kept as they are, so the palette stays coherent with the kit.
4. **Write `src/shared/maps/<map>.zig`.** Start from `racing.zig`. Set `.ready = true` only when the map passes the quality bar below. In `build`:
   - `api.building(b, k.buildings[i], x, z, yaw)` places a building on the lowest ground under it and adds its collision boxes.
   - `b.put(kit.of(.name), x, z, yaw, scale)` places a prop on the terrain.
   - `b.putAt(kind, pos, yaw, scale)` places a prop at an exact height.
   - `api.box(b, ...)` adds an invisible solid.
   - `b.mass(min, max, tone)` adds a coloured solid box.
   - `api.scatter(b, kinds, count, x0, z0, x1, z1, keep)` scatters props.
   - `b.rng` gives deterministic randomness.

   Set terrain with `height` and `ground`, the light with `palette`, the horizon colour with `backdrop` and `floor_y` (set `floor_y` to the sea level for sea maps), and the flags `aircraft` (parks the jet on `runway`), `grip` and `runway`.
5. **Spots.** `.spots = api.autoSpots` finds spawns, loot and parking on open ground. Write your own `spots(gpa)` if the layout needs hand-picked spawns. It must set `world.spawns`, `world.spawn_yaws`, `world.weapon_spots`, `world.drone_anchors` and `world.vehicle_spots`. See `islands.zig` `islandSpots`.
6. **Build.** Use your own install prefix so parallel builders never overwrite each other:

   ```
   ~/.local/opt/zig-x86_64-linux-0.17.1/zig build -Drelease -j2 --prefix /tmp/battle-<map>
   ```

   If the build fails inside another map's file, that builder is mid-edit. Wait a minute and retry; never edit their file.
7. **Shots.** `tools/shot.sh <map> ~/.cache/maps/<map>_<view>.jpg "x,y,z,yaw,pitch" /tmp/battle-<map>`. It starts its own hidden Xvfb (a free display is picked automatically), runs the game with `DF_MAP=<map>`, captures the window and cleans up. `yaw` 0 looks toward +z. `SHOT_WAIT` changes the wait (default 20 s), `SHOT_HUD=1` keeps the HUD. Take:
   - at least 3 wide views from different map edges, including one looking back from the far side
   - at least 3 street-level views at eye height
   - one gun shot with the HUD

   Then compare them with `~/.cache/polyfork/<map>/cover.jpg`.
8. **Preview.** Make `src/client/assets/ui/maps/<map>.png` from your best wide shot:

   ```
   ffmpeg -i shot.jpg -vf "scale=480:240:force_original_aspect_ratio=increase,crop=480:240" <png>
   ```

## Quality bar

Every map must reach at least Polygun Arena level before `.ready = true`:

- dense, handcrafted-feeling layouts, never props sprinkled on open ground
- rich prop clutter at every corner: crates, barrels, signs, fences, plants, vehicles, debris
- clear lit and shade sides on buildings and terrain
- varied silhouettes and heights: tall landmarks, low cover, rooftops, ramps
- no bald empty ground, no blank walls, no flat single-colour areas
- readable cover and lanes: several routes, flanks and sightlines broken by cover

Compare your shots with the kit cover and this bar. If it doesn't pass, iterate before reporting. Show wide views honestly, not only the nice corner.

## Rules

- **No animate beings:**
  - no people, figures, workers, animals, dinosaurs, fish, statues of beings, skeletons or skulls
  - skip such models entirely
  - `pf.py` strips sub-meshes whose names match its `SKIP` pattern, but check every render yourself
- **No religious buildings or symbols:** no churches, chapels, crosses, bell towers or temples, and no religious words in names.
- **No faces** on anything.
- **Lighting:** the shader gives sun shading only. Do not add shadows, reflections, glow tricks or post effects.
- **Size:** 300 m minimum, 500 m maximum across the playable area (`play` is the half-size: 150 to 250).
- **Instancing:** each prop kind is one instanced draw, so reuse kinds rather than exporting near-duplicates. Keep one map's kit under about 60 kinds.
- **Collision must match the meshes:**
  - you can't walk through walls or into invisible walls
  - nothing at head height across walkable paths
  - stairs are ramps
- **Budget:**
  - RAM under 300 MB
  - each map's `props/<map>/` under 6 MB (check with `du -sh`), so the whole APK stays under about 150 MB
  - check `TRIS` from `mapkit.sh`: aim for under 150k triangles per kit
- **Testing:** hidden Xvfb only (`tools/shot.sh` does this). Never open a window on the user's display `:1`.
- **Git and stable:** don't commit, push, install the APK or touch `~/dronefire-stable`. The coordinator does that.
- **Credits:** Polyfork is already in the README credits.
